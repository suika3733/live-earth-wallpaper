## v3.0.7 图片显示 + 窗口控制修复（8-13 续）

### 两个 bug 根因
1. **图片不显示**：前端 fetch 到图片路径后只更新元数据，从未把图片渲染到 `.preview-placeholder` 的 background-image。三个面板（APOD/卫星/SDO）全都有此 bug。
2. **窗口控制缺失**：`initWindowControls()` 在 DOMContentLoaded 时检测 `window.pywebview.api`，但 pywebview 6.2.1 的 API 注入晚于 DOMContentLoaded，导致检测失败按钮被隐藏。

### 修复
- server.py 加 `_cache_path_to_url()` 助手：绝对路径 → `/api/image-cache/<relative>` URL
  - 卫星/SDO 响应加 `url` 字段
  - APOD 响应加 `preview_url` 字段（避免覆盖远程 `url`/`hdurl`）
- index.html 加 `setPreviewImage(sel, url)` 设置 background-image（cover/center/no-repeat）
- `initWindowControls()` 改为监听 `pywebviewready` 事件重试，`bindWindowControls()` 幂等化

### 关键教训
- pywebview 6.x 用 `pywebviewready` 事件，不能只在 DOMContentLoaded 检测 API
- dict key 字符串在 Python 3.11+ marshal 字节码里可能不在 co_consts，验证用 co_names（函数名/方法名）

## 单实例保护（8-13 续2）

### 根因
用户同时运行多个 exe（`LiveEarthWallpaper.exe` dist 目录 + `LiveEarthWallpaper_v3.0.7.exe` releases 归档），两个进程都监听 51234 端口，请求被旧进程随机处理，导致用户看到旧界面。

### 修复
- launcher.py 加 `_is_already_running()`：用 socket connect_ex 检测 51234 端口是否被占用
- main() 开头检测，已运行则弹 MessageBox 提示并退出
- 避免多实例端口冲突

### 关键教训
- pywebview 6.2.1 的 JS API 注入时机：`api.js` 先建 `window.pywebview={api:{}}`，`finish.js` 在 `on_navigation_completed` 后调用 `_createApi()` 并派发 `pywebviewready`。所以 window 控制按钮初始化必须监听 `pywebviewready`，不能只靠 DOMContentLoaded。
- 归档 exe 命名带版本号（`LiveEarthWallpaper_v3.0.7.exe`）会导致进程名不同，用户可能同时运行两个版本。命名需谨慎。

## 水印功能增强 + 时间校准（8-13 续3）

### 需求

2. 水印大小/字体/位置可编辑
3. 水印增加当前系统时间

### 修复
- **时间 bug 根因**：前端 `new Date().toISOString()` 返回 UTC 时间，却硬编码标注 `(UTC+8)`。改为 `formatLocalTime()` 用本地时区。
- **wallpaper.py**：`watermark_image()` 扩展 `font_size`/`font_family`/`position`/`show_sys_time` 参数；新增 `_get_font()` 按字体名取字体；`_FONT_FAMILIES` 映射（msyh/simhei/simsun/arial）；位置四角；系统时间用 `datetime.now().strftime()`。
- **config.py**：DEFAULT_CONFIG 加 `wm_font_size`(0=自适应)/`wm_font_family`/`wm_position`/`wm_show_sys_time`。
- **server.py**：watermark-and-set 透传水印参数；config 白名单加 4 个 wm_ 字段。
- **index.html**：设置面板加水印控件（字号/字体/位置/系统时间开关）；`getWmSettings()`+`wmPayload()` 辅助函数；三个 set wallpaper 用本地时间 + 水印设置。

### 关键教训
- JS `toISOString()` 是 UTC，本地时间要用 `getFullYear/getMonth/getDate/getHours/getMinutes` 手动格式化。

## SDO 波段修复 + 字号档位 + 连通性测试（8-13 续4）

### SDO 失败根因
前端侧边栏 8 个波段（continuum/magnetogram/0211/0193/0094/0131 等），但后端 `SDO_BANDS` 只有 5 个（0304/0171/0304pfss/0171pfss/HMIIC），命名不匹配导致 6/8 波段返回 "Unknown SDO band" 失败。

### 修复
- **providers/sdo.py**：SDO_BANDS 补全到 11 个波段（0304/0171/0211/0193/0094/0131/0335/1600/1700/HMIIC/HMIB），移除无效的 pfss；新增 `test_sdo_connectivity()` 连通性测试函数。
- **server.py**：新增 `/api/sdo/bands`（波段列表）、`/api/sdo/test`（连通性测试）端点。
- **index.html**：侧边栏波段改为动态加载（与后端一致）；设置面板加"默认 SDO 波段"下拉 + "测试连通性"按钮 + 结果展示。
- **字号**：`wm_font_size` 从数字输入改为档位下拉（自动/小14/中18/大22/特大28）。

### 关键教训
- NASA SDO latest 图片 URL 格式：`https://sdo.gsfc.nasa.gov/assets/img/latest/latest_{resolution}_{band}.jpg`，band 支持 0304/0171/0211/0193/0094/0131/0335/1600/1700/HMIIC/HMIB。
- 前后端枚举值必须严格对齐，否则静默失败（fetch_sdo_image 返回 None，前端显示"获取失败"）。

### 补充：GitHub 大文件上传方式
- `python | curl --data-binary @-` 管道方式上传 34MB zip 时频繁 HTTP 100/连接重置失败。
- **可靠方式**：系统 Python requests 直接读文件上传（`requests.post(url, headers, data=open(...).read())`），状态码 201 成功。curl 管道在沙箱环境下不稳定，改用 requests 更稳。

## 动态系统时间水印（8-13 续8）

### 需求
水印里的"当前系统时间"之前是设置壁纸时写死的静态值，用户希望动态跟随系统时间变化。

### 实现
- server.py 加全局 `_active_wallpaper`（保存当前壁纸的原始图片路径 + 水印参数）
- `_dynamic_time_loop()` 后台线程每 60 秒检查：若 `_active_wallpaper.show_sys_time=True`，用当前 `datetime.now()` 重新调用 `watermark_image()` 生成新水印并 `set_wallpaper()`
- watermark-and-set 端点设置壁纸后保存参数到 `_active_wallpaper`，`show_sys_time=True` 时启动刷新线程
- 线程 daemon=True，软件退出自动结束

### 注意
- 每 60 秒刷新一次（显示到秒），现代 Windows 桌面合成不会明显闪烁
- 只在 show_sys_time=True 时刷新，False 时水印时间静态（影像时间）
